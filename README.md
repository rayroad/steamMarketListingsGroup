# Steam Market Listings Group

在 Steam 市场商品详情页和“我当前的出售挂单”页面增加聚合、筛选与批量操作。当前版本 **3.1.2**，使用原版容器、商品图文和 Steam 深色样式。

## 商品详情页

| 模式 | 每行内容 | 勾选范围 |
| --- | --- | --- |
| 按价格 | 跨日期合并相同买方价格，显示日期范围和数量 | 该价格的全部挂单 |
| 按日期 | 同一天、同一买方价格一行；同日不同价格分别成行 | 该日期与价格的全部挂单 |
| 原版 | 保留 Steam 实际列表节点，每件物品一行 | 单件挂单 |

默认按价格显示，切换模式会保存偏好。已选物品在三种模式间保留；聚合行支持半选状态。顶部“全选”选择当前商品的全部已提取挂单。

## 操作

1. 勾选单件或聚合行，点击“下架选中”或“重新上架选中”。
2. 点击第一行最右侧的“全部下架”或“全部重新上架”，处理全部挂单，忽略勾选状态。
3. 聚合行直接点击“下架 / 重新上架”处理整组；原版行点击“修改”后选择操作。
4. 重新上架时填写“您将收到”或“买方支付”，查看总到手金额后确认。所有操作都有确认步骤，批量执行期间禁止重复启动。

下架成功后列表自动更新。重新上架会等待物品回库并获取新的资产 ID，成功后更新挂单 ID、日期和价格。上架失败的物品从挂单列表移除，并提示已回到库存；需要手机/邮件确认或响应不明确时提示“待核实/确认”，请在 Steam 完成确认并刷新核对。

## 当前出售挂单页

访问 [我当前的出售挂单](https://steamcommunity.com/market/activelistings)，脚本自动逐页加载正常出售的挂单，显示 `已加载 / 总数`。可取消、继续加载或刷新；HTTP 错误、重复分页或数量变化会提示数据不完整。暂挂与待确认记录由原生页面保留处理，不混入批量操作。

| 模式 | 每行内容 |
| --- | --- |
| 按物品（默认） | 同应用、同商品、同价格及同数量的挂单合并，显示数量、日期范围及到手合计 |
| 按日期 | 同日期、同商品和同价格一行，不同价格分别成行 |
| 原版 | 按原版逐件字段布局展示，每页 50 行；可查看全部已加载记录 |

筛选与操作区域在滚动时吸顶；搜索和排序的标签与表单左右排列。展开筛选过高时可在吸顶区域内部滚动。

不同商品不会仅因价格相同而合并。真实 Steam 原生列表节点保留；点击“收起增强”可恢复查看它。

1. **组合筛选**：名称/游戏关键词（空格组合）、游戏/应用、类别、日期范围、最少挂单天数、买方或卖方金额范围、同商品最少挂单数、通常价格缺失/偏离比例。
2. **排序**：最新上架、挂单最久、数量最多、到手合计最高、单价最低和名称。
3. **多选**：聚合行勾选整组，支持半选、跨模式及本地分页保留；“全选筛选结果”只选择筛选匹配的已加载数据，筛选外的已选数量单独提示。
4. **批量操作**：“下架选中 / 重新上架选中”处理所有已选记录；右侧“下架筛选结果 / 重新上架筛选结果”处理当前筛选范围。确认弹窗明确数量和隐藏选择。加载期间禁用搜索、排序、筛选、模式切换、勾选及交易；加载结束、取消或失败后自动恢复，可先取消加载再操作已加载部分。
5. **分别定价**：重新上架先按商品分别填写到手价或买方价，再预览数量、每组价格与总到手金额。每组使用自己的 appid/contextid/发行商费率，串行执行；回库匹配排除库存原有物品并校验 classid/instanceid。

“通常价格”和“当前最低价”使用接口的两个独立字段；无数据时显示 `—`，不会用最低价冒充通常价格。旧币挂单使用接口换算后的钱包金额。未识别到游戏名称时显示应用 ID。

总览页的堆叠挂单金额按整笔展示；数量大于 1、待改价确认或关键资产/费率信息不完整的记录仍可下架，但重新上架需使用 Steam 原生操作。实时列表不是锁定的交易快照，加载期间发生的成交/新增可能要求重新扫描。操作后本地同步，并提示刷新核对；没有跨会话交易缓存。

## 安装或更新

1. 安装浏览器扩展 [Tampermonkey](https://www.tampermonkey.net/)。
2. 安装 [脚本](https://github.com/rayroad/steamMarketListingsGroup/raw/master/steam-market-listings-group.user.js)，或将本地 `steam-market-listings-group.user.js` 全部内容粘贴到已有脚本编辑器并保存。
3. 确认 Tampermonkey 中版本为 **3.1.2**，刷新 Steam 市场商品详情页。

商品详情页默认有 1 件挂单即可显示（总览页不受该阈值限制）。可通过 Tampermonkey 菜单调整“最少检测上架数量阈值”；已有保存值会继续生效。

## 技术与验证

运行时为单文件 IIFE，无构建步骤和外部依赖；详情页从 `unsafeWindow.SSR.loaderData` 提取挂单，总览页使用与原生相同的 `QueryMyListings` 查询接口。交易使用 Steam 登录会话；会话缺失时读取其他 Steam 页面作为回退。

已依据 2026-11-26 的 Steam 新版挂单 DOM 实现。原版行不提供挂单 ID，因此按初始日期、价格和出现顺序匹配 SSR 数据；无法匹配的行不会绑定脚本交易操作。Steam 页面重绘后自动恢复增强面板和选择状态。

开发验证使用 Node.js 24+ 和仅供测试的 jsdom：

```sh
npm ci
npm run check
npm test
```

29 项离线测试覆盖两个页面的模式、筛选、分页加载/取消/错误恢复、选择、重绘、跨游戏交易参数、回库匹配及成功/失败状态同步。官方分页响应已通过真实只读请求核验；浏览器已检查 80 笔模拟挂单、定价弹窗与 390px 窄屏。未执行真实下架/上架，安装后请用少量挂单验证。
