## Project

Single-file Tampermonkey userscript (`steam-market-listings-group.user.js`, version 3.0.2, MIT) for Steam market listing detail pages. Enhances the existing native sell-order container with price/date aggregation and the original list mode, per-item or whole-group selection, batch delist and price-change relist. Runtime has no build step or dependencies; `package.json` only supplies offline jsdom regression tests. Distributed via Greasy Fork; homepage on keylol.

## Architecture (single IIFE, top-down)

1. **Metadata header** — `@match *://steamcommunity.com/market/listings/*`, `@run-at document-end`. Grants: `GM_addStyle`, `GM_getValue`, `GM_setValue`, `GM_registerMenuCommand`, `unsafeWindow`.
2. **CONFIG + menu command** — `CONFIG.minOrders` (via `GM_getValue`, default 0). Panel is skipped when order count `<= minOrders`. Users change it via Tampermonkey menu "⚙ 设置最少检测上架数量阈值" (prompt → validate non-negative integer → `GM_setValue`; takes effect after refresh). No in-page settings UI by design.
3. **Styles** — `GM_addStyle`, native Steam CSS variables (`--color-dull-5`, `--color-accent-8`, `--color-text-body-title`, etc.) with fallbacks. The original blue-bordered container stays visible. The injected toolbar and aggregate table match native dark rows and product artwork. Native grid has `.smg-native-grid`, hidden only in aggregate/collapsed modes. Dialogs, progress and Toast remain; focus rings and reduced-motion rules included. Action colors (3.0.2): delist red, relist blue, clear/cancel neutral; toolbar, aggregate rows and native-action dialogs share these colors. Confirmation buttons use the action-specific red/blue class.
4. **Utilities** — `escapeHtml()` (mandatory for all server/user data); `formatDateParts` / `tsToDateKey` / `tsToDateTime` (`rtListed` is a Unix **seconds** timestamp); `getSessionId()` (2.6.2: sync local chain — `unsafeWindow.g_sessionID` → `meta[name="sessionid"]` → anchored cookie regex → `scanSSRForSessionId()` deep object scan of `unsafeWindow.SSR` (handles nested/escaped JSON strings) → `extractSessionIdFromText(innerHTML)` with regexes tolerant of escaped quotes `\\"` and case variants `sessionID`/`sessionId`, value constrained to 8–48 hex chars). Batch handlers call `await resolveSessionId()` which falls back to `fetchSessionIdFromRemote()` (GET `/my/inventory` then `/market/`, extract from fetched HTML) when all local sources fail; success cached in `_sessionIdCache`; final failure logs `[SMG] sessionid not found via ...` warn naming every source tried. **Currency subsystem (2.6.0)**: module-level `currencyMeta` (`{code, decimals, unit, symbol, prefix}`, `unit = 10^decimals`) resolved ONCE per session by `resolveCurrency()` in `main()` right after extraction — priority: ① `g_rgWalletInfo.wallet_currency` → `GetCurrencyCode`/`CURRENCY_ID_TO_CODE` (partial table, verified ids only), ② longest-prefix match of first order's price via `SYMBOL_TO_CODE`, ③ USD default + warn log. All display/parsing/fee code goes through `getCurrencyMeta()`, `formatMoney(cents)` (prefix symbol + space, e.g. `¥ 10.50`; suffix currencies appended), and `parseAmount(str)` (strips symbol/whitespace, treats comma as thousands-separator when `.` also present or exactly 3 digits follow, else as European decimal comma; returns lowest-unit integer). `CURRENCY_META` covers ~40 currencies incl. zero-decimal (JPY/KRW/TWD/IDR/CLP/COP/CRC/VND) and 3-decimal (KWD); unlisted codes fall back to USD-style meta. SSR-origin price strings are shown as-is; only reconstructed prices (relist write-back, dialogs, confirm text) use `formatMoney`.
5. **UI helpers** — `showLoading()`/`hideLoading()` full-screen overlay shown from `main()` start until panel injected or flow aborted; `showConfirmDialog(message, opts)` returns a Promise, used as delist/relist confirmation — optional `opts.title`/`opts.okText` override the default 确认下架 wording (relist passes 确认重新上架, 2.5.4). **Toast notifications (2.7.0)**: `showToast(message, cls)` creates a bottom-center floating toast (`.smg-toast-container` fixed at `bottom:24px; left:50%`, auto-removes after 5 s with slide-in/out animation). `showStatus(el, text, cls, autoHide)` routes `autoHide=true` messages (validation errors, 已取消, completion) to `showToast` instead of the panel status element; progress messages (no autoHide) still write to the panel's `.smg-delist-status`, but fall back to toast when the element is detached from DOM (e.g. after `refreshPanel` rebuilds the panel).
6. **Data extraction** — `extractOrders()` iterates `unsafeWindow.SSR.loaderData` entries (string entries are `JSON.parse`d, failures skipped), finds the first `data.myOrders.rgSellOrders` with length > 0, maps to `{listingid, assetid, appid, classid, rtListed, dateKey, dateTime, buyerPrice, sellerPrice}`.
7. **Grouping** — `groupOrders()` → date groups keyed by `dateKey` (sorted desc), each holding a price Map (`buyerPrice` → orders sorted by `rtListed` desc), `sortedPrices` (ascending by numeric part, currency symbols stripped for comparison), and `totalCount`.
8. **Rendering and selection (3.0.0)** — `buildViewRows(orders, mode)` groups by buyer-price string across dates (`price`), by date + buyer-price string (`date`), or per item (`original`). Date mode produces separate rows for different prices on one date. `renderSummary()` renders heading, persistent mode switches, selected-item toolbar with all-item actions aligned to its far right (3.0.1; price/quantity filter row removed), totals and aggregate table. `viewMode` is saved with GM storage (default price); `selectedIds` is a module-level Set of string listingids. `setItemsSelected()` selects each underlying order; `updateSelectionUI()` updates group/all checkboxes, indeterminate state, native per-item boxes and selected count. Selection survives mode switches and hydration. `refreshPanel()` prunes dead ids, rebuilds only `#smg-root`, preserves collapse state, and synchronizes native rows. Seller totals prefer server sellerPrice; successful relists now retain the exact submitted seller amount.
9. **Unified operations (3.0.0)** — all controls call `runBatch(action, scope, rowItems)` with `all` / `selected` / `row`. `selectBatchOrders()` snapshots matching items newest-first and rejects unknown scopes (3.0.1). A module-level `batchBusy` lock covers preparation, dialogs, session resolution and execution; finally clears progress, regroups, refreshes and restores controls. All panel controls and native modify/select controls are disabled while busy. Relist shows linked seller/buyer price dialog, then quantity + both amounts + total confirmation, then resolves sessionid/app context. `removeListing()` sends sequential credentialed POST to `/market/removelisting/{id}`, accepts `{}` and rejects explicit `success:false/0`. `executeDelist()` immediately removes successful orders from module state; failures remain selected. `executeRelist()` removes each old listing locally immediately after delist, polls inventory by classid for the returned assetid (up to 10 s, 1.5 s intervals; used ids excluded), then POSTs `/market/sellitem/` with **price = seller received in the lowest currency unit**. Explicit sell failures retry once after 1.5 s; network/JSON ambiguity is not retried because the request may have succeeded. Success with listingid writes new id/assetid/current timestamp/buyerPrice/sellerPrice and returns the item to allOrders. Confirmation-required or missing-listingid responses remove the obsolete id and report 待核实/确认; explicit failures report 已回到库存. Items are separated by 800 ms. Session, currency, fee and context fallback utilities remain; context = page sources → app 753:6 → default 2, no remote context probing. `configureDialog()` adds labels, Escape cancel and focus trapping. Price submit recomputes buyer total from seller input.
10. **Native DOM integration (verified 2026-11-26, app 5052450)** — the original heading's grandparent is a four-column grid (`--grid-columns: 2fr max-content max-content 1fr`); native rows use `--grid-columns: subgrid`, four children (name/image, date, price, modify). No listingid attribute exists. `findTargetElement()` finds the native heading + subgrid, with a CSS-variable container fallback for other languages. `ensurePanel()` builds the full toolbar/table off-DOM and inserts it **inside the original container**, before its native grid. `syncNativeList()` preserves actual native nodes, prepends item checkboxes and intercepts 修改 in capture phase to show script actions using current item identity (prevents stale React listingid closures after relist). `nativeSnapshots` preserves initial date/price + item identity so re-rendered stale SSR DOM can be mapped and removed orders stay hidden; identical date/price copies are matched by occurrence. Unmatched rows are not bound to script transactions. Only HTTPS Steam image hosts are reused. `nativeBindings` maps DOM rows to item objects; disconnected entries are pruned.
11. **Injection and main flow** — extract SSR synchronously → gate at `length <= minOrders` → save native snapshots → resolve currency once → group → locate container → inject. Startup retains backoff polling (50 ms × 10 then 200 ms, 30 attempts) and body observer with 15 s timeout. Ongoing `reinjectObserver` watches body child-list/subtree, coalesces with a microtask and re-finds the current native container/grid (never reinserts into a detached old parent); restores current selection and busy/progress state. Mutations wholly inside `#smg-root` are ignored; native text is only rewritten when changed to avoid observer loops.

## Key Technical Details

- Uses `unsafeWindow` to access Steam's SSR data (`SSR.loaderData`, `g_sessionID`) — never replace with `window`.
- Runs at `document-end`; SSR data is read synchronously at start, so extraction must happen before any DOM waiting.
- All UI strings are Chinese (zh-CN). Keep them in Chinese.
- Console logs use `[SMG]` prefix; `[OPT]` comments mark optimization rationale.
- Bump `@version` on every functional change — Greasy Fork auto-update depends on it.

## Conventions

- Single IIFE with `'use strict'`, plain JS, no build step, no dependencies.
- All HTML built via template literals; `escapeHtml()` is mandatory for any user/server-derived data.
- Off-DOM construction: always render panel HTML completely into a detached element before inserting, so the panel appears fully formed (no intermediate paint).
- Element IDs use the `smg-` prefix (`#smg-panel`, `#smg-root`, `#smg-loading`); CSS classes `smg-*`.
- State lives in module-level `allOrders` / `grouped`; mutations (e.g. delist) re-derive both and re-render via `refreshPanel`. Batch handlers must NOT shadow these names as parameters — assign to the module-level variables directly, otherwise `reinjectObserver` re-injection and later button clicks silently operate on stale data.

## Lessons & Pitfalls (verified)

- **Reference loader reviewed (Steam 许可分类器 v2.5.8, user attachment, 2026-11-26)**: `autoLoadAllPages` follows `a.license_paginator_next` using sequential same-origin fetch + DOMParser, appends tbody rows with DocumentFragment, and updates via ingestRows; PAGE_DELAY=150ms, MAX_PAGES=3000. localStorage holds ordered fingerprints (date/name/type + occurrence number), IndexedDB holds row HTML, TTL=7 days. Warm path restores HTML and stops incremental fetching on a page with no new fingerprints; legacy path clicks load-more and stops after three unchanged counts. Reuse scheduling/progress/incremental aggregation ideas, not license selectors or freshness assumptions. Market orders can disappear through sales/delist and relist with new ids: deduplicate by listingid and verify live completeness; do not use seven-day HTML snapshots as transaction targets or assume a cache-hit page proves the remaining data is unchanged. Reference loader's handled HTTP/parse/empty-page exits can still reach a success Toast because only escaping exceptions set crashed=true; keep partial/error/end states distinct. Its base-fingerprint page-wrap guard is unsafe for market pages with many visually identical legitimate orders. Active-listings pagination response/next cursor still requires live inspection before choosing a fetch adapter; this review did not implement that adapter.

- **Active listings research (2026-11-26, no implementation yet)**: inspected `/market/activelistings` in Edge read-only. Tab showed 890 total sell orders; DOM initially had 50 rows and grew to 75 after scrolling. This is incremental loading, so loaded-row aggregates are not account-wide totals. Rows have named grid cells `nameblock`, `date`, `price`, optional `recent` (UI label 通常价格), and `modify`; unlike detail pages they include product links, app/game text and item category. Observed appids 5052450 and 753; community item subtype also named its originating game's trading cards. Native 修改 opens a modal with 移除挂单 / 更改价格 and 当前市场低价; closed without submitting. 通常价格 is a separate UI field and its exact definition was not verified; do not label it current lowest price. Proposed grouping must include product identity (appid + market listing identity), never merge different products solely by price. Existing runBatch/executeRelist assume the first item's appid/context/price for the whole batch, so cross-product relisting needs per-product/per-app preparation before supporting this route. Current userscript @match still only includes `/market/listings/*`.

- **Action color cascade (3.0.2)**: semantic button rules must follow generic native-style button backgrounds and cover hover without overriding disabled opacity. showConfirmDialog receives the action explicitly so relist confirmations use the blue class rather than the red delist default.


- **Toolbar simplification (3.0.1)**: removed the price/quantity row and its handlers/state. All-item actions live in `.smg-all-actions` inside the first toolbar; flex `margin-left:auto` keeps the pair at the far right and wrapping supports narrow widths. Keep progress/status elements outside the removed controls so transaction feedback survives.


- **Native integration verified for v3.0.0 (2026-11-26)**: source defaults minOrders to 0. The sample helmet page has 43 native sell rows; native DOM supplies no listingid. Preserve initial date/price signatures independently of mutable relist data, and bind identical rows by occurrence. Automated tests cover stale SSR DOM after a delist. Native 修改 must use the current item object after relist, not the original React callback.
- **React hydration deletes injected DOM**: Steam's React 18 SSR hydration rewrites the listing area; fixed-delay waits (300ms/500ms) were proven insufficient. The current defense is three layers: (1) data pre-extraction independent of DOM; (2) backoff polling + MutationObserver dual detection for the target element; (3) `reinjectObserver` re-injects whenever the panel disappears. Do not regress to plain `setTimeout` delays.
- **Off-screen build prevents flash**: inserting DOM then hiding (`display:none`/`visibility:hidden`) still paints intermediate states or reserves layout; build the full panel off-DOM and insert atomically. Queries on a detached panel must use `panelEl.querySelector`, not `document.getElementById`.
- **SSR readiness checks**: don't infer "data ready" from an empty-array initial (`[] !== null` is always true); use explicit null checks / ready flags when gating on extraction results.
- **Native selector compatibility**: v3.0.0 replaces the exact inline-style selector with native heading + subgrid structure and CSS-variable fallback. If Steam changes row child order, subgrid styling or heading markup, check findTargetElement/syncNativeList first. Unmatched rows must not be bound to script operations.
- **React error #418 in the console is usually NOT ours** (user log, app 2963550): hydration-mismatch errors (`Minified React error #418`) thrown from Steam's bundles are caused by DOM-modifying browser extensions (e.g. gamesforfarm, translators) mutating server HTML before hydration — verify via timeline: if the error precedes our "Target element found" log, our injection (which only hides the container + inserts a sibling) cannot be the cause. Aborted hydration even stabilizes the injected panel; no action needed unless the panel itself disappears.
- **Delist behavior**: removes newest listings first (`rtListed` DESC), requests are sequential (no parallelism) to avoid rate limiting; panel refreshes from filtered local data without reload.
- **Relist API contract**: `/market/sellitem/` requires `price` in the lowest currency unit (e.g. ¥10.50 → 1050) plus valid `appid`/`contextid`/`assetid`; **`price` is the SELLER-RECEIVED amount (您将收到), not the buyer total** — Steam computes the buyer price by adding fees on top (user-reported, fixed 2.4.9; submitting the buyer total overprices the listing by the fee percentage). HTTP 200 alone is not proof — the JSON body may contain `success: false` (e.g. market cooldown), so both must be checked. If `removelisting` succeeds but `sellitem` fails, the item has returned to the inventory and the status text must say so.
- **assetid changes when an item returns from the market** (verified via user testing, app 2963550): after `removelisting`, calling `sellitem` with the original (pre-listing) assetid fails with "指定的物品不再存在于您的库存…" because the returned asset gets a NEW assetid. Fix: after delisting, poll `/my/inventory/json/{appid}/{ctx}` and match `rgInventory` entries by `classid` (collected in `extractOrders` since 2.4.4) to obtain the current assetid before `sellitem`. A fixed settle delay alone is NOT enough. (Related: while listed, the asset is absent from inventory JSON entirely — see next item.)
- **Listed assets are absent from inventory JSON** (verified via user testing, 2.4.3 probe failed): once an item is listed on the market it is held by Steam and disappears from `/my/inventory/json/{appid}/{ctx}` `rgInventory`, so assetid-matching against inventory NEVER works for *listed* items — but it IS the correct way to re-locate an asset *after* delisting (see previous item). `GET /market/mylistings/` does contain contextid per listing, but API probing for contextid proved unreliable (misses, wrong cached values) — in 2.4.7 all such probing was dropped in favor of the reference script's static map + default '2' strategy.
- **Never let contextid resolution block the relist dialog**: in 2.4.2–2.4.5 contextid was resolved *before* the price dialog and any probe failure aborted the whole flow — the user could never reach the dialog. The historical reference implementation (market.uset.js, not present in this repository) simply uses `APP_CONTEXT[appid] || '2'` with no probing at all. Current design (2.4.7, fully aligned with the reference): dialogs first, contextid = page sources → `KNOWN_APP_CONTEXT` static map → default '2', no API probing, no GM cache (a wrongly cached probe value caused "delist succeeded but relist failed" in 2.4.6); an incorrect default only fails the `sellitem` call, which is retried and the Steam-returned `message` is logged and shown in the status text.
- **Relist needs inventory re-location between delist and sellitem**: `sellitem` only works once the item is back in the inventory AND with its current assetid (which may have changed on return). Poll inventory by classid (see the assetid lesson); if lookup times out, fall back to the original assetid and retry once after 1.5 s; keep an ~800 ms gap between items to avoid rate limiting.
- **SSR `rgSellOrders` verified schema** (app 3218600): each sell order contains exactly `appid, classid, assetid, listingid, rtListed (unix seconds), strBuyerPrice, strSellerPrice` — **no contextid and no fee info**; prices are preformatted strings like "¥ 0.95". Use the order's `appid` as the authoritative appid source for sellitem calls.
- **sessionid sources are unreliable on new SSR pages** (user-reported 2.6.1–2.6.2: 重新上架 showed 无法获取会话ID even after the first page-source fix): the React-SSR market page may omit `g_sessionID` global, the `meta[name="sessionid"]` tag, AND a readable `sessionid` cookie — same class of problem as the missing legacy globals (see below). Two escalation stages were needed: (1) 2.6.1's plain regex over innerHTML still missed because SSR payloads can be ESCAPED JSON strings (`\\"sessionid\\":...`) or nested inside `SSR.loaderData` — fix: `extractSessionIdFromText` tolerates `\\` before quotes/colons and case variants, value constrained to 8–48 hex to avoid false positives; plus `findSessionId` recursive object scan (depth 8, strings >20 chars regex-checked). (2) If the page genuinely contains no sessionid, `resolveSessionId()` fetches another Steam page (`/my/inventory` → `/market/`) with credentials and extracts from there. General rule: never fail hard on the first few sources for any page-embedded value; always end the chain with a broad tolerant scan and a remote fallback, and make the failure warn name every source tried so users can diagnose.
- **Legacy globals missing on new SSR pages**: the React-SSR market listing page does NOT reliably define legacy globals (`g_appId`, `g_rgAppContextData`) — reading only them causes "无法获取应用上下文" failures. appid resolves from the URL path; contextid may be absent from SSR data ENTIRELY (verified on app 3218600: SSR entries contain `appid` but no contextid-like key at any depth). Reported by user on the relist button; fixed in 2.4.2–2.4.7 (final approach: static map + default '2' like the reference script).
- **Steam fee algorithm** (verified against official economy_v2.js/market.js, reference script market.uset.js, and user's real listing data): fees are computed from the seller-received amount — `steam_fee = max(floor(received * wallet_fee_percent + wallet_fee_base), effMin)`, `publisher_fee = max(floor(received * pub_rate), effMin)` (0 when pub_rate = 0), buyer pays = received + both. Publisher rate: `g_rgAppContextData[appid].market_pubfee_rate` first, then `g_rgWalletInfo.wallet_publisher_fee_percent_default` (default 0.10); Steam rate from `g_rgWalletInfo.wallet_fee_percent` (default 0.05). **Dec 2025 Steam change — TWO parts**: (1) certain currencies (JPY/IDR/UAH/CLP/COP/TWD/KZT/CRC/UYU/KRW/VND) use `Math.round` instead of `Math.floor`; (2) **the per-fee minimum was raised to $0.01-equivalent (CNY ¥0.07, was ¥0.01)** — verified against user data: received 0.85 → buyer 1.00 (Steam fee 0.07 + publisher 0.08), received 0.60 → buyer 0.74 (both fees hit the ¥0.07 minimum). Below ≈¥1.6 the effective fee rate exceeds the classic 15%; old `min=1` formulas under-quote the buyer price in the low-price range. Do NOT delegate to page functions (`GetTotalWithFees` etc.) — new SSR pages may not expose them; buyer→received reverse must be iterative because of the floors.
- **Price display reconstruction** (2.6.0): SSR only gives formatted strings (`strBuyerPrice` like "¥ 10.50") and those are displayed unchanged; when writing a new price back locally, `formatMoney(buyerCents)` builds it from the resolved `currencyMeta` (correct decimals, prefix/suffix symbol, space after prefix symbol). The exact format remains a best-effort approximation for suffix currencies (no thousands grouping). The old "copy prefix via `/^[^0-9]*/` + toFixed(2)" approach was removed because it broke for zero-decimal and suffix currencies.
- **Currency adaptation rules** (2.6.0): (1) adapting currency must NEVER change the `sellitem` contract — `price` stays the seller-received amount in the LOWEST currency unit (`unit = 10^decimals`, e.g. JPY unit 1, KWD unit 1000); never hardcode `×100`/`/100`/`toFixed(2)` for money. (2) Currency is session-constant: resolve once into module-level `currencyMeta` (in `main()` after extraction) and reuse everywhere — re-detecting per call risks inconsistent fee rounding/display. (3) `MIN_FEE_BY_CURRENCY` only lists currencies with real-data verification (currently CNY:7); for others rely on `wallet_fee_minimum` — do not invent minimum-fee values. (4) `CURRENCY_ID_TO_CODE` stays partial on purpose (verified ids 25/32/33/37 kept as-is); unknown ids fall through to symbol inference rather than a guessed mapping. (5) Ambiguous symbols resolve by longest-prefix-first (`MX$` before `$`) with bare `$`→USD, `kr`→SEK documented defaults.
- **refreshPanel wipes transient state**: `refreshPanel()` rebuilds `#smg-root` innerHTML from scratch, so any status text / progress-bar state set before the call is lost. Write completion messages after refreshing (against the freshly rendered elements); references to pre-refresh elements become detached but keeping them for the in-loop phase is fine.
- **Parameter shadowing silently breaks module-state sync** (found by code review, fixed 2.5.4): `handleDelist(allOrders, grouped, ...)` params shadowed the module-level variables, so `allOrders = allOrders.filter(...)` only rebound the parameter — module state stayed stale, and `reinjectObserver` re-injection (which reads module-level `allOrders`) resurrected already-delisted items after React hydration wiped the panel. Handlers now take no state params and mutate module-level `allOrders`/`grouped` directly.
- **sellitem creates a NEW listing — write back its listingid** (fixed 2.5.4): `removelisting` destroys the old listingid and the `sellitem` success response JSON contains the new one; without writing it back, the panel row carries a dead id — any later delist of that row fails and the row can never be removed without a page refresh. Symmetrically, items delisted but failing `sellitem` twice must be REMOVED from local data (`unlistedSet` filter), since they are back in inventory.
- **Batch lock must precede awaits (3.0.0)**: checking only on handler entry and setting busy after dialogs leaves a race. runBatch acquires synchronously, holds through every dialog/network step, and releases in finally; reinjection restores disabled controls and progress. Do not rely on disabled buttons alone.
- **Price dialog must recompute on submit**: the linked inputs only sync on `input` events; submitting the two raw field values lets a user desync them (e.g. appending digits to the buyer field), showing a wildly wrong 买方支付 in the secondary confirm. Since `sellitem` only takes `receivedCents`, treat it as the single source of truth and recompute `buyerCents` via `calcBuyerTotal` on OK.

## Test / Debug Notes

- Debug on a market listing page where the logged-in account owns more than `minOrders` listings; follow `[SMG]` logs for the full chain: extraction → target found/polling → panel injected.
- **Verify the running script version before diagnosing**: when editing the local `.user.js` directly, Tampermonkey keeps the old copy until the script is reinstalled/updated — stale log wording is the giveaway (e.g. the 2.6.1 warn `sessionid not found via g_sessionID / meta / cookie / page source` vs 2.6.2's `... / SSR scan / page source / remote fetch`; also check the running script's `@version` in the Tampermonkey dashboard or `GM_info.script.version`). A "fix didn't work" report can actually be the pre-fix code still executing.
- Delisting/relisting hit real Steam endpoints — verify with a small quantity or a test listing only.
- Relist flow: select items/groups → 重新上架选中 button → price dialog with linked 您将收到/买方支付 inputs (edit either side, the other auto-updates; empty input is blocked, Enter confirms; on submit the buyer amount is recomputed from 您将收到) → secondary confirm (titled 确认重新上架); cancel at either dialog only sets 已取消 status.
- Relist-all flow: 全部重新上架 button → price dialog (custom message: 将全部 N 件商品以新价格重新上架) → secondary confirm (titled 确认重新上架, body says 全部); processes ALL orders regardless of selection.
- Non-progress notifications (validation errors, 已取消, completion) appear as bottom-center floating Toast messages (5 s auto-dismiss) instead of the panel's status text area. Progress messages during batch operations still appear in the panel.
- Batch mutex: starting any second batch while one runs shows 已有批量操作进行中，请稍候 and does nothing.
- Setting `minOrders` to 0 via the menu command makes the panel appear with any non-empty listing set (note the gate is `length <= minOrders`, so 0 orders still skips).
- Currency (2.6.0): console shows `[SMG] Currency resolved: XXX (via wallet info|via symbol)` or the USD-fallback warn. CNY regression data points: received 0.85 → buyer 1.00, received 0.60 → 0.74. Relist price dialog labels show the currency symbol, placeholder/linked values follow the currency's decimals (JPY: integer, no `0.00`); inputs accept thousands commas (`1,234.56`) and European decimal commas (`2,50`). Confirm dialog and panel write-back render via `formatMoney` (e.g. `¥ 120` for JPY).
