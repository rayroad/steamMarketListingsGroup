## Project

Single-file Tampermonkey userscript (`steam-market-listings-group.user.js`, version 2.7.2, MIT) that runs on Steam Community market listing detail pages. It extracts the current user's sell orders from `unsafeWindow.SSR.loaderData`, groups them by listing date and buyer price, hides the default listing container, and injects a summary panel with batch-delist (下架) and price-change relist (重新上架) tools. Distributed via Greasy Fork (`@updateURL`/`@downloadURL`); homepage on keylol.

## Architecture (single IIFE, top-down)

1. **Metadata header** — `@match *://steamcommunity.com/market/listings/*`, `@run-at document-end`. Grants: `GM_addStyle`, `GM_getValue`, `GM_setValue`, `GM_registerMenuCommand`, `unsafeWindow`.
2. **CONFIG + menu command** — `CONFIG.minOrders` (via `GM_getValue`, default 5). Panel is skipped when order count `<= minOrders`. Users change it via Tampermonkey menu "⚙ 设置最少检测上架数量阈值" (prompt → validate non-negative integer → `GM_setValue`; takes effect after refresh). No in-page settings UI by design.
3. **Styles** — one `GM_addStyle` block, Steam dark theme: `#1b2838`/`#1d1f23` backgrounds, `#3d4450` borders, `#66c0f4` accent, `#c7d5e0` text. Covers panel, summary table, price tags, delist controls, full-screen loading overlay (`#smg-loading`, z-index 99998), confirm dialog (z-index 99999), progress bar, toast notifications (`.smg-toast-container` fixed bottom-center, `.smg-toast` with slide-in animation), green relist-all button (`.smg-relist-all-btn`).
4. **Utilities** — `escapeHtml()` (mandatory for all server/user data); `formatDateParts` / `tsToDateKey` / `tsToDateTime` (`rtListed` is a Unix **seconds** timestamp); `getSessionId()` (2.6.2: sync local chain — `unsafeWindow.g_sessionID` → `meta[name="sessionid"]` → anchored cookie regex → `scanSSRForSessionId()` deep object scan of `unsafeWindow.SSR` (handles nested/escaped JSON strings) → `extractSessionIdFromText(innerHTML)` with regexes tolerant of escaped quotes `\\"` and case variants `sessionID`/`sessionId`, value constrained to 8–48 hex chars). Batch handlers call `await resolveSessionId()` which falls back to `fetchSessionIdFromRemote()` (GET `/my/inventory` then `/market/`, extract from fetched HTML) when all local sources fail; success cached in `_sessionIdCache`; final failure logs `[SMG] sessionid not found via ...` warn naming every source tried. **Currency subsystem (2.6.0)**: module-level `currencyMeta` (`{code, decimals, unit, symbol, prefix}`, `unit = 10^decimals`) resolved ONCE per session by `resolveCurrency()` in `main()` right after extraction — priority: ① `g_rgWalletInfo.wallet_currency` → `GetCurrencyCode`/`CURRENCY_ID_TO_CODE` (partial table, verified ids only), ② longest-prefix match of first order's price via `SYMBOL_TO_CODE`, ③ USD default + warn log. All display/parsing/fee code goes through `getCurrencyMeta()`, `formatMoney(cents)` (prefix symbol + space, e.g. `¥ 10.50`; suffix currencies appended), and `parseAmount(str)` (strips symbol/whitespace, treats comma as thousands-separator when `.` also present or exactly 3 digits follow, else as European decimal comma; returns lowest-unit integer). `CURRENCY_META` covers ~40 currencies incl. zero-decimal (JPY/KRW/TWD/IDR/CLP/COP/CRC/VND) and 3-decimal (KWD); unlisted codes fall back to USD-style meta. SSR-origin price strings are shown as-is; only reconstructed prices (relist write-back, dialogs, confirm text) use `formatMoney`.
5. **UI helpers** — `showLoading()`/`hideLoading()` full-screen overlay shown from `main()` start until panel injected or flow aborted; `showConfirmDialog(message, opts)` returns a Promise, used as delist/relist confirmation — optional `opts.title`/`opts.okText` override the default 确认下架 wording (relist passes 确认重新上架, 2.5.4). **Toast notifications (2.7.0)**: `showToast(message, cls)` creates a bottom-center floating toast (`.smg-toast-container` fixed at `bottom:24px; left:50%`, auto-removes after 5 s with slide-in/out animation). `showStatus(el, text, cls, autoHide)` routes `autoHide=true` messages (validation errors, 已取消, completion) to `showToast` instead of the panel status element; progress messages (no autoHide) still write to the panel's `.smg-delist-status`, but fall back to toast when the element is detached from DOM (e.g. after `refreshPanel` rebuilds the panel).
6. **Data extraction** — `extractOrders()` iterates `unsafeWindow.SSR.loaderData` entries (string entries are `JSON.parse`d, failures skipped), finds the first `data.myOrders.rgSellOrders` with length > 0, maps to `{listingid, assetid, appid, classid, rtListed, dateKey, dateTime, buyerPrice, sellerPrice}`.
7. **Grouping** — `groupOrders()` → date groups keyed by `dateKey` (sorted desc), each holding a price Map (`buyerPrice` → orders sorted by `rtListed` desc), `sortedPrices` (ascending by numeric part, currency symbols stripped for comparison), and `totalCount`.
8. **Rendering** — `renderSummary()` builds the entire panel HTML string: header (total count + 收起/展开 toggle), table (日期 / 价格分布 / 数量, with 合计 row showing 卖方到手合计 via `computeTotalReceived()`), and the delist section from `renderDelistSection()`. `computeTotalReceived(orders, fallbackAppId)` (2.7.1) sums each order's seller-received amount: uses `parseAmount(sellerPrice)` when available, falls back to `calcReceivedFromTotal(parseAmount(buyerPrice), appid)` for relisted items whose `sellerPrice` was cleared. `refreshPanel()` re-renders `#smg-root` after delisting/relisting; `bindPanelEvents()` attaches toggle + delist + relist + relist-all handlers.
9. **Batch delist & relist** — `handleDelist(removeAll)` (2.5.4: no longer takes `allOrders`/`grouped` params — handlers read/write module-level state directly; parameter shadowing previously caused the module state to never be updated): filters orders by selected buyer price, sorts by `rtListed` **DESC** (newest removed first), shows confirm dialog, then sequential `POST https://steamcommunity.com/market/removelisting/{listingid}` with `sessionid` form body (`credentials: 'include'`), updates progress bar per item, finally filters removed listings out of module-level `allOrders`, regroups into module-level `grouped`, and calls `refreshPanel()` — no page reload. The 全部下架 button (`#smg-delist-all-btn`, flex `margin-left:auto` so it hugs the row's right edge, 2.5.3) calls `handleDelist` with `removeAll=true`: price/qty selectors are ignored, ALL orders are queued (rtListed DESC), and the confirm dialog shows 即将下架全部 N 件. **Batch mutual exclusion (2.5.4, expanded 2.7.0, refactored 2.7.2)**: module-level `batchBusy` flag guards both flows — entry returns with 已有批量操作进行中 if a batch is running; all FOUR buttons (`#smg-delist-btn`, `#smg-delist-all-btn`, `#smg-relist-btn`, `#smg-relist-all-btn`) are disabled during a batch and restored at the end via `setAllBatchButtonsDisabled(disabled)` helper (2.7.2: eliminates duplicated 4-button enable/disable patterns across `handleDelist` and `executeRelist`). The flag is more reliable than button-disabling alone because `reinjectObserver` re-renders fresh (enabled) buttons mid-batch. **Relist orchestration extraction (2.7.2)**: `handleRelist()` and `handleRelistAll()` no longer duplicate the sessionid/appid/dialog/confirm/contextid pipeline. Instead, each handler only handles item selection + dialog configuration, then delegates to `prepareAndExecuteRelist(toRemove, statusEl, dialogConfig)` which owns the shared orchestration: `batchBusy` check → `resolveSessionId()` → `getAppContext()` → `showPriceDialog(dialogConfig.oldPrice, count, appId, dialogConfig.dialogMsg)` → `showConfirmDialog(dialogConfig.confirmMsg(...), dialogConfig.confirmOpts)` → contextid fallback → `executeRelist()`. `dialogConfig` carries `dialogMsg`, `oldPrice`, `confirmMsg(received, buyer, count)`, `confirmOpts`. `executeRelist(toRemove, sessionid, appId, contextId, receivedCents, buyerCents, statusEl)` remains the core batch-processing loop, now using `setAllBatchButtonsDisabled()` instead of individual button refs. `handleRelist()` reuses the same price/qty selectors: validates → gets sessionid/appid → **`showPriceDialog()` immediately** (contextid never blocks the dialog; linked 您将收到 / 买方支付 inputs, Steam multisell-style — 2×2 CSS grid layout with labels above inputs, no fee breakdown row (removed 2.5.1), Enter supported; returns `{buyerCents, receivedCents}`) → secondary `showConfirmDialog()` (title/button 确认重新上架, shows both amounts) → **then** resolves contextid non-blocking → sequential per-item: `removelisting` → **poll `GET /my/inventory/json/{appid}/{ctx}` every 1.5 s (max 10 s) matching `rgInventory[].classid` to re-locate the returned asset's (possibly NEW) assetid** (`waitForReturnedAsset`/`findReturnedAssetId`; `usedAssetIds` Set prevents picking the same asset twice in a batch; falls back to the original assetid if classid missing or timeout) → `POST /market/sellitem/` with `sessionid/appid/contextid/assetid/amount=1/price` (**price = 卖方到手价 `receivedCents`，NOT buyer pays** — Steam adds fees on top to compute the buyer price; verified by user, 2.4.9; lowest currency unit), retry once after 1.5 s on failure; 800 ms gap between items. **On sellitem success the NEW `listingid` from the response JSON is written back to the item (2.5.4)** — `sellitem` creates a brand-new listing and the old listingid was destroyed by `removelisting`; without write-back the panel row could never be delisted again. Items whose `removelisting` succeeded but `sellitem` failed twice are collected in `unlistedSet` and **removed from module-level `allOrders`** at the end (they are back in inventory; keeping them displayed desyncs panel vs server). contextid resolution (matches reference script market.uset.js exactly, never hard-fails): (1) `getAppContext(appidHint)` page sources — legacy `g_rgAppContextData[appId]` (array `[{id}]` or object/`contexts` shapes) → deep recursive scan of `SSR.loaderData` (`scanSSRForContextId`/`findContextId`, max depth 8) → regex over `document.documentElement.innerHTML`; appid comes from the order's own `appid` field first, then `unsafeWindow.g_appId`, then URL path; (2) **`KNOWN_APP_CONTEXT[String(appId)] || DEFAULT_CONTEXT_ID` ('2'; Steam community items app 753 → '6')** — the same static-map + default strategy as the reference script; the old mylistings/inventory API probing (`probeContextId`) was removed in 2.4.7 because probe misses/incorrect cached values caused relist failures. `sellitem` failures now parse and log `data.message` (`[SMG] Relist: sellitem failed ... message: ...`) and surface it in the final status text. **全部重新上架 (2.7.0)**: `handleRelistAll()` button (`#smg-relist-all-btn`, green gradient, placed after 全部下架) ignores price/qty selectors, takes ALL orders (rtListed DESC), shows `showPriceDialog` with custom message (将全部 N 件商品以新价格重新上架), secondary confirm titled 确认全部重新上架, then delegates to the shared `executeRelist`. `showPriceDialog` accepts an optional 4th parameter `dialogMsg` to override the default description text. **Price dialog total display (2.7.1)**: below the 2x2 price grid, a live-updating line shows 您将总共收到: ¥ X.XX (共 N 件) — `updateTotal(receivedCents)` is called on every `input` event from either field, computing `receivedCents * count`; when the user edits the buyer field, `receivedCents` is first reverse-computed via `calcReceivedFromTotal` before updating the total. Fee math (aligned with market.uset.js, 2.4.9; Dec 2025 minimum-fee fix 2.5.0): `getWalletInfo()` caches `g_rgWalletInfo` params (`wallet_fee_percent`, `wallet_fee_base`, `wallet_fee_minimum`, `wallet_publisher_fee_percent_default`, currency) plus `currencyCode`/`decimals`/`unit` taken from the shared `currencyMeta` (2.6.0) — fallback values are NOT cached so late-loading wallet info is picked up; when wallet info is absent entirely (new SSR pages) the currency comes from `resolveCurrency()`'s symbol inference → USD fallback so currency-dependent rules still apply; publisher rate overridden by `g_rgAppContextData[appId].market_pubfee_rate` when present. `calcBuyerTotal` = per fee: `max(roundOrFloor(received * rate [+ base for Steam fee]), effMin)` where `effMin = max(wallet_fee_minimum, MIN_FEE_BY_CURRENCY[code])` (CNY → 7 = ¥0.07, per the Dec 2025 change) and rounding is `Math.round` for CURRENCY_CODES_TO_ROUND (JPY/IDR/UAH/CLP/COP/TWD/KZT/CRC/UYU/KRW/VND) else `Math.floor`; buyer = received + both fees. `calcReceivedFromTotal` = iterative estimation (≤10 rounds, terminates when total matches or stops changing). Page functions `GetTotalWithFees`/`GetItemPriceFromTotal` are no longer delegated to (new SSR pages may not expose them). **Price dialog submit (2.5.4)**: `receivedCents` is the single source of truth — `buyerCents` is always recomputed via `calcBuyerTotal` on OK, so a manually desynced buyer input can no longer show a misleading amount in the secondary confirm. Successful items are mutated in place (new `listingid`, new `rtListed`=now, reconstructed `buyerPrice` via `formatMoney(buyerCents)` adapting decimals/symbol to the wallet currency (2.6.0), `sellerPrice` cleared) then regrouped + refreshed. Status distinguishes 成功 / 下架失败 / 上架失败(已回到库存); `sellitem` response is additionally checked for `success === false`. Panel status text goes through `showStatus(el, text, cls, autoHide)` (2.7.0: non-progress messages with `autoHide=true` now route to bottom-center floating Toast via `showToast()` instead of writing to the panel's `.smg-delist-status`; progress messages without autoHide still write to the panel element, with automatic Toast fallback when the element is detached from DOM after `refreshPanel`).
10. **Injection & hydration defense** — `findTargetElement()` queries an element by its exact inline `style` attribute string (`--background: var(--color-dull-5); ...`) — fragile, depends on Steam's current markup. `ensurePanel()` builds `#smg-root` fully off-DOM (innerHTML rendered before insertion), hides the target container (`display:none`), inserts the wrapper right after it. `reinjectObserver` (MutationObserver on target's parent, subtree) re-injects whenever `#smg-panel` disappears; observer is disconnected before recreating to prevent leaks.
11. **Main flow** — `main()` (on `DOMContentLoaded` or immediately if already loaded): show loading → **extract data first (DOM-independent)** → abort if `<= minOrders` → `resolveCurrency()` (one-shot currency detection, 2.6.0) → pre-group → try immediate target lookup → fallback: backoff polling (50ms × 10, then 200ms, max 30 attempts) + MutationObserver on `document.body` direct children → 15 s timeout disconnects observer and hides loading.

## Key Technical Details

- Uses `unsafeWindow` to access Steam's SSR data (`SSR.loaderData`, `g_sessionID`) — never replace with `window`.
- Runs at `document-end`; SSR data is read synchronously at start, so extraction must happen before any DOM waiting.
- All UI strings are Chinese (zh-CN). Keep them in Chinese.
- Console logs use `[SMG]` prefix; `[OPT]` comments mark optimization rationale.
- Bump `@version` on every functional change — Greasy Fork auto-update depends on it.

## Conventions

- Single IIFE with `'use strict'`, plain JS, no build step, no dependencies.
- All HTML built via template literals; `escapeHtml()` is mandatory for any user/server-derived data.
- Off-DOM construction: always render panel HTML completely into a detached element before inserting, so the panel appears fully formed (no intermediate paint).
- Element IDs use the `smg-` prefix (`#smg-panel`, `#smg-root`, `#smg-loading`); CSS classes `smg-*`.
- State lives in module-level `allOrders` / `grouped`; mutations (e.g. delist) re-derive both and re-render via `refreshPanel`. Batch handlers must NOT shadow these names as parameters — assign to the module-level variables directly, otherwise `reinjectObserver` re-injection and later button clicks silently operate on stale data.

## Lessons & Pitfalls (verified)

- **React hydration deletes injected DOM**: Steam's React 18 SSR hydration rewrites the listing area; fixed-delay waits (300ms/500ms) were proven insufficient. The current defense is three layers: (1) data pre-extraction independent of DOM; (2) backoff polling + MutationObserver dual detection for the target element; (3) `reinjectObserver` re-injects whenever the panel disappears. Do not regress to plain `setTimeout` delays.
- **Off-screen build prevents flash**: inserting DOM then hiding (`display:none`/`visibility:hidden`) still paints intermediate states or reserves layout; build the full panel off-DOM and insert atomically. Queries on a detached panel must use `panelEl.querySelector`, not `document.getElementById`.
- **SSR readiness checks**: don't infer "data ready" from an empty-array initial (`[] !== null` is always true); use explicit null checks / ready flags when gating on extraction results.
- **Target selector fragility**: `findTargetElement()` matches an exact inline style string. If Steam changes its styling, injection silently fails (loading overlay until the 15 s timeout). This is the first thing to check when the panel stops appearing.
- **React error #418 in the console is usually NOT ours** (user log, app 2963550): hydration-mismatch errors (`Minified React error #418`) thrown from Steam's bundles are caused by DOM-modifying browser extensions (e.g. gamesforfarm, translators) mutating server HTML before hydration — verify via timeline: if the error precedes our "Target element found" log, our injection (which only hides the container + inserts a sibling) cannot be the cause. Aborted hydration even stabilizes the injected panel; no action needed unless the panel itself disappears.
- **Delist behavior**: removes newest listings first (`rtListed` DESC), requests are sequential (no parallelism) to avoid rate limiting; panel refreshes from filtered local data without reload.
- **Relist API contract**: `/market/sellitem/` requires `price` in the lowest currency unit (e.g. ¥10.50 → 1050) plus valid `appid`/`contextid`/`assetid`; **`price` is the SELLER-RECEIVED amount (您将收到), not the buyer total** — Steam computes the buyer price by adding fees on top (user-reported, fixed 2.4.9; submitting the buyer total overprices the listing by the fee percentage). HTTP 200 alone is not proof — the JSON body may contain `success: false` (e.g. market cooldown), so both must be checked. If `removelisting` succeeds but `sellitem` fails, the item has returned to the inventory and the status text must say so.
- **assetid changes when an item returns from the market** (verified via user testing, app 2963550): after `removelisting`, calling `sellitem` with the original (pre-listing) assetid fails with "指定的物品不再存在于您的库存…" because the returned asset gets a NEW assetid. Fix: after delisting, poll `/my/inventory/json/{appid}/{ctx}` and match `rgInventory` entries by `classid` (collected in `extractOrders` since 2.4.4) to obtain the current assetid before `sellitem`. A fixed settle delay alone is NOT enough. (Related: while listed, the asset is absent from inventory JSON entirely — see next item.)
- **Listed assets are absent from inventory JSON** (verified via user testing, 2.4.3 probe failed): once an item is listed on the market it is held by Steam and disappears from `/my/inventory/json/{appid}/{ctx}` `rgInventory`, so assetid-matching against inventory NEVER works for *listed* items — but it IS the correct way to re-locate an asset *after* delisting (see previous item). `GET /market/mylistings/` does contain contextid per listing, but API probing for contextid proved unreliable (misses, wrong cached values) — in 2.4.7 all such probing was dropped in favor of the reference script's static map + default '2' strategy.
- **Never let contextid resolution block the relist dialog**: in 2.4.2–2.4.5 contextid was resolved *before* the price dialog and any probe failure aborted the whole flow — the user could never reach the dialog. Reference implementation (market.uset.js) simply uses `APP_CONTEXT[appid] || '2'` with no probing at all. Current design (2.4.7, fully aligned with the reference): dialogs first, contextid = page sources → `KNOWN_APP_CONTEXT` static map → default '2', no API probing, no GM cache (a wrongly cached probe value caused "delist succeeded but relist failed" in 2.4.6); an incorrect default only fails the `sellitem` call, which is retried and the Steam-returned `message` is logged and shown in the status text.
- **Relist needs inventory re-location between delist and sellitem**: `sellitem` only works once the item is back in the inventory AND with its current assetid (which may have changed on return). Poll inventory by classid (see the assetid lesson); if lookup times out, fall back to the original assetid and retry once after 1.5 s; keep an ~800 ms gap between items to avoid rate limiting.
- **SSR `rgSellOrders` verified schema** (app 3218600): each sell order contains exactly `appid, classid, assetid, listingid, rtListed (unix seconds), strBuyerPrice, strSellerPrice` — **no contextid and no fee info**; prices are preformatted strings like "¥ 0.95". Use the order's `appid` as the authoritative appid source for sellitem calls.
- **sessionid sources are unreliable on new SSR pages** (user-reported 2.6.1–2.6.2: 重新上架 showed 无法获取会话ID even after the first page-source fix): the React-SSR market page may omit `g_sessionID` global, the `meta[name="sessionid"]` tag, AND a readable `sessionid` cookie — same class of problem as the missing legacy globals (see below). Two escalation stages were needed: (1) 2.6.1's plain regex over innerHTML still missed because SSR payloads can be ESCAPED JSON strings (`\\"sessionid\\":...`) or nested inside `SSR.loaderData` — fix: `extractSessionIdFromText` tolerates `\\` before quotes/colons and case variants, value constrained to 8–48 hex to avoid false positives; plus `findSessionId` recursive object scan (depth 8, strings >20 chars regex-checked). (2) If the page genuinely contains no sessionid, `resolveSessionId()` fetches another Steam page (`/my/inventory` → `/market/`) with credentials and extracts from there. General rule: never fail hard on the first few sources for any page-embedded value; always end the chain with a broad tolerant scan and a remote fallback, and make the failure warn name every source tried so users can diagnose.
- **Legacy globals missing on new SSR pages**: the React-SSR market listing page does NOT reliably define legacy globals (`g_appId`, `g_rgAppContextData`) — reading only them causes "无法获取应用上下文" failures. appid resolves from the URL path; contextid may be absent from SSR data ENTIRELY (verified on app 3218600: SSR entries contain `appid` but no contextid-like key at any depth). Reported by user on the relist button; fixed in 2.4.2–2.4.7 (final approach: static map + default '2' like the reference script).
- **Steam fee algorithm** (verified against official economy_v2.js/market.js, reference script market.uset.js, and user's real listing data): fees are computed from the seller-received amount — `steam_fee = max(floor(received * wallet_fee_percent + wallet_fee_base), effMin)`, `publisher_fee = max(floor(received * pub_rate), effMin)` (0 when pub_rate = 0), buyer pays = received + both. Publisher rate: `g_rgAppContextData[appid].market_pubfee_rate` first, then `g_rgWalletInfo.wallet_publisher_fee_percent_default` (default 0.10); Steam rate from `g_rgWalletInfo.wallet_fee_percent` (default 0.05). **Dec 2025 Steam change — TWO parts**: (1) certain currencies (JPY/IDR/UAH/CLP/COP/TWD/KZT/CRC/UYU/KRW/VND) use `Math.round` instead of `Math.floor`; (2) **the per-fee minimum was raised to $0.01-equivalent (CNY ¥0.07, was ¥0.01)** — verified against user data: received 0.85 → buyer 1.00 (Steam fee 0.04 + publisher 0.08), received 0.60 → buyer 0.74 (both fees hit the ¥0.07 minimum). Below ≈¥1.6 the effective fee rate exceeds the classic 15%; old `min=1` formulas under-quote the buyer price in the low-price range. Do NOT delegate to page functions (`GetTotalWithFees` etc.) — new SSR pages may not expose them; buyer→received reverse must be iterative because of the floors.
- **Price display reconstruction** (2.6.0): SSR only gives formatted strings (`strBuyerPrice` like "¥ 10.50") and those are displayed unchanged; when writing a new price back locally, `formatMoney(buyerCents)` builds it from the resolved `currencyMeta` (correct decimals, prefix/suffix symbol, space after prefix symbol). The exact format remains a best-effort approximation for suffix currencies (no thousands grouping). The old "copy prefix via `/^[^0-9]*/` + toFixed(2)" approach was removed because it broke for zero-decimal and suffix currencies.
- **Currency adaptation rules** (2.6.0): (1) adapting currency must NEVER change the `sellitem` contract — `price` stays the seller-received amount in the LOWEST currency unit (`unit = 10^decimals`, e.g. JPY unit 1, KWD unit 1000); never hardcode `×100`/`/100`/`toFixed(2)` for money. (2) Currency is session-constant: resolve once into module-level `currencyMeta` (in `main()` after extraction) and reuse everywhere — re-detecting per call risks inconsistent fee rounding/display. (3) `MIN_FEE_BY_CURRENCY` only lists currencies with real-data verification (currently CNY:7); for others rely on `wallet_fee_minimum` — do not invent minimum-fee values. (4) `CURRENCY_ID_TO_CODE` stays partial on purpose (verified ids 25/32/33/37 kept as-is); unknown ids fall through to symbol inference rather than a guessed mapping. (5) Ambiguous symbols resolve by longest-prefix-first (`MX$` before `$`) with bare `$`→USD, `kr`→SEK documented defaults.
- **refreshPanel wipes transient state**: `refreshPanel()` rebuilds `#smg-root` innerHTML from scratch, so any status text / progress-bar state set before the call is lost. Write completion messages after refreshing (against the freshly rendered elements); references to pre-refresh elements become detached but keeping them for the in-loop phase is fine.
- **Parameter shadowing silently breaks module-state sync** (found by code review, fixed 2.5.4): `handleDelist(allOrders, grouped, ...)` params shadowed the module-level variables, so `allOrders = allOrders.filter(...)` only rebound the parameter — module state stayed stale, and `reinjectObserver` re-injection (which reads module-level `allOrders`) resurrected already-delisted items after React hydration wiped the panel. Handlers now take no state params and mutate module-level `allOrders`/`grouped` directly.
- **sellitem creates a NEW listing — write back its listingid** (fixed 2.5.4): `removelisting` destroys the old listingid and the `sellitem` success response JSON contains the new one; without writing it back, the panel row carries a dead id — any later delist of that row fails and the row can never be removed without a page refresh. Symmetrically, items delisted but failing `sellitem` twice must be REMOVED from local data (`unlistedSet` filter), since they are back in inventory.
- **Cross-flow batch mutex needs a module-level flag, not just disabled buttons** (fixed 2.5.4, expanded 2.7.0): per-flow button-disabling was asymmetric (delist left 重新上架 clickable and vice versa), and `reinjectObserver` re-renders fresh enabled buttons mid-batch anyway. `batchBusy` flag checked at handler entry + all FOUR buttons (`#smg-delist-btn`, `#smg-delist-all-btn`, `#smg-relist-btn`, `#smg-relist-all-btn`) disabled during the batch via `setAllBatchButtonsDisabled(disabled)` (2.7.2: single helper replaces duplicated 4-button patterns in `handleDelist` and `executeRelist`, reducing maintenance when adding new buttons).
- **Price dialog must recompute on submit**: the linked inputs only sync on `input` events; submitting the two raw field values lets a user desync them (e.g. appending digits to the buyer field), showing a wildly wrong 买方支付 in the secondary confirm. Since `sellitem` only takes `receivedCents`, treat it as the single source of truth and recompute `buyerCents` via `calcBuyerTotal` on OK.
